# 액추에이터 개체차 보정 — 인수인계

브랜치 `DMY_actuator_variance` 의 작업 문서다. **이 파일부터 읽고 시작한다.**

## 목표

6개 액추에이터의 **개체 차이를 없앤다.** 같은 지령에 같은 거동이 나오게 하는 것이
최종 목표이고, 그러려면 먼저 개체차가 **무엇이 얼마나** 다른지를 재야 한다.

첫 단계는 이것 하나다:

> **축마다 목표 압력을 컨트롤러에 주고, 압력을 추종시키고, 그때의 엔코더 각도를
> 로깅한다. 위치 피드백은 쓰지 않는다.**

위치 루프를 넣으면 개체차가 피드백에 흡수되어 안 보인다. **개루프 정특성이라야
개체차가 드러난다.**

## 지금 상태 — 무엇이 이미 있고 무엇이 없나

### 이미 있다 (그대로 쓴다)

| | 무엇 | 검증 |
|---|---|---|

| `scripts/sensor_monitor.py` | CAN + Teensy raw/각도/수신율 한 화면 | 사용 중 |

| `docs/축별_액추에이터_각도제어_절차.md` | 터미널 구성·기동·측정·함정. **운용 절차는 전부 여기 있다** | — |
| `docs/데드존측정_튜닝_절차.md` | 채널 압력 PID 의 전제 | — |

**압력 제어 성능은 건드리지 않는다.** 채널 PID·데드존 표·레일 제어는 현재 상태를
유지한다. 이 작업은 그 위에서 각도만 관찰한다.

### 없다 (만들어야 한다)

1. **축간 비교 분석.** `actuator_map.py --analyze` 는 **한 축**의 마찰만 뗀다.
   6축을 겹쳐 놓고 편차를 내는 도구가 없다.
2. **개체차 보정 형식.** 축별 보정을 어디에 어떤 모양으로 둘지 안 정해졌다.

## ★ 시작 전에 반드시 — 3~6축 엔코더 보정이 **남의 장비 값**이다

`config/powerpack_config.yaml` 의 `TeensyEncoder.channels`:

```yaml
"0": { raw_0deg: 24370.0, raw_90deg: 4650.0 }   # 1축  ← 20260914 이 장비에서 실측
"1": { raw_0deg: 26940.0, raw_90deg: 8420.0 }   # 2축  ← 20260914 이 장비에서 실측
"2": { raw_0deg: 27500.0, raw_90deg: 7330.0 }   # 3축  ← **다른 장비 값. 미검증**
"3": { raw_0deg: 28060.0, raw_90deg: 7890.0 }   # 4축  ← 미검증
"4": { raw_0deg: 28850.0, raw_90deg: 8680.0 }   # 5축  ← 미검증
"5": { raw_0deg: 28775.0, raw_90deg: 8605.0 }   # 6축  ← 미검증
```

**엔코더 보정이 틀리면 개체차 측정은 통째로 무의미하다.** 보정 오차와 실제
개체차가 구별되지 않는다. 1축은 재측정에서 **13° 나 밀렸다** — 이 크기의 오차가
3~6축에 남아 있을 수 있다.

그래서 **0번 작업은 3~6축 엔코더 2점 보정 재측정**이다.

```zsh
# 팔을 0° 와 90° 에 놓고 raw 를 읽는다 (런치를 띄운 채로 된다)
cd ~/claude_tutorial/src/can_powerpack/scripts
python3 sensor_monitor.py          # 엔코더 표의 raw 열
```

`deg = (raw − raw_0deg) × 90 / (raw_90deg − raw_0deg)`. raw 가 각도에 **반비례**
한다(1축 −219 카운트/도). 부호가 뒤집히면 배선이 바뀐 것이다.

두 점을 정확히 90° 벌려 잡기 어려우면 아무 두 각도에서 읽고 역산한다:

```
raw_0deg  = r₁ − (r₂−r₁)·θ₁/(θ₂−θ₁)
raw_90deg = raw_0deg + (r₂−r₁)·90/(θ₂−θ₁)
```

yaml 만 고치면 되고 **재빌드는 필요 없다.** 런치만 다시 띄운다.

## 측정 계획

### ★ 핵심 설계 결정 — 축마다 **똑같은 차압 목록**을 쓴다

`--preset lift90` 은 **쓰지 않는다.** 프리셋은 "각도를 고르게 훑도록" 축의 강성에
맞춰 차압을 역산하므로, 축마다 **다른 압력**이 나간다. 그러면 개체차가 차압
목록에 흡수되어 사라진다.

개체차를 보려면 **같은 입력에 대한 서로 다른 출력**을 봐야 한다. `--diffs` 로
고정 목록을 주고 6축에 그대로 돌린다.

```zsh
python3 actuator_map.py --axis N \
    --diffs 0,8,16,24,32,40,48,54,60,66,72 \
    --centers 101.3,108,115 \
    --ang-max 88
```

- 이 목록은 1·2축 실측에서 잡은 것이다. 1축은 차압 57 kPa 에서 60°, 2축은
  55 kPa 에서 49° 였다. 72 kPa 면 1축이 80° 부근, 2축이 60° 부근까지 간다.
- **도달 못 하는 축은 `--ang-max` 에 안 걸린다** — 그 축은 그냥 낮은 각도에서
  멈추고, 그 차이가 곧 우리가 재려는 값이다.
- 반대로 **무른 축이 있으면 88° 에 걸려 중단된다.** 그건 정보다 — 그 축만
  목록을 줄여 다시 돌리고, 비교에는 겹치는 구간만 쓴다.
- 축당 약 14분. 6축이면 1시간 반이다.

### 압력 조건 — 레일을 올려 놓고 잰다

```zsh
python3 rail_ref.py --hold-ref 200 30      # 별도 터미널, 측정 내내 유지
```

차압 72 kPa 면 중심압 115 에서 **P+ 가 151 kPa** 까지 간다. 레일 기본값 160 으로는
여유가 9 kPa 뿐이라 채널이 목표압을 못 만든다 — 20260914_100318 에서 이것 때문에
**P+ 가 −4.6 kPa 모자랐다.** 그 상태로 재면 개체차가 아니라 압력 부족을 재게 된다.

**측정 중 압력 추종을 반드시 확인한다.** `actuator_map.py` CSV 의
`p_pos_meas − p_pos_ref` 가 ±1 kPa 를 넘는 행이 있으면 그 점은 버리거나 다시 잰다.

### 순서

```
0) 3~6축 엔코더 2점 보정 재측정 → yaml → 런치 재기동
1) rail_ref.py --hold-ref 200 30   (측정 내내 유지)
2) 축 1~6 을 같은 --diffs 로 순서대로     (축당 14분)
3) 축간 비교 분석 도구 작성 → 개체차 정량화
4) 보정 방식 결정
```

## 3단계에서 뽑아야 할 것

`actuator_map.py --analyze` 가 한 축에서 내주는 것:

- **토크 이득** dτ/d(차압) [N·m/kPa]
- **마찰 반폭 f** [kPa] (왕복 두 곡선 간격의 절반)
- 중앙 곡선 `mid(θ)` = 그 각도를 만드는 데 필요한 차압

축간 비교로 내야 할 것 (아직 도구 없음):

| 지표 | 왜 |
|---|---|
| **오프셋** — 같은 차압에서 각도 차 | 조립·프리로드 차이. 상수 보정으로 지워진다 |
| **이득** — 기울기 d(차압)/dθ 의 축간 비 | 액추에이터 강성 차이. 1축 0.86 vs 2축 1.15 kPa/° 로 **34 % 차이**가 이미 확인됐다 |
| **마찰 f 의 축간 산포** | 이건 **피드포워드로 못 지운다** — 밴드 안에서 각도가 지령으로 결정되지 않으므로 각 축의 정확도 하한이 된다 |
| **비선형성** | 토크 이득이 차압에 따라 떨어진다 (1축 0.046 → 0.024~0.035 N·m/kPa). 축마다 떨어지는 모양이 다르면 상수 보정으로 안 된다 |

### 이미 나온 기준값 (1·2축, 20260914 엔코더 재보정 반영)

| | 1축 | 2축 |
|---|---|---|
| 마찰 반폭 f | 4.31 kPa | 3.82 kPa |
| 플랜트 기울기 d(차압)/dθ | 0.86 kPa/° | **1.15 kPa/°** |
| 맵이 덮는 각도 | 8.6 ~ 73.5° | 13.9 ~ 49.3° |
| 같은 차압 55 kPa 에서 | ≈ 58° | ≈ 49° |

**두 축이 같은 압력에서 9° 차이가 난다.** 이게 이 작업이 지우려는 것이다.

다만 이 두 값은 `--preset` 으로 뜬 것이라 **차압 목록이 서로 다르다.** 위 계획대로
같은 목록으로 다시 떠야 엄밀한 비교가 된다.

## 반드시 지킬 것

- **`control_mode:=0`** 으로 런치한다. yaml 기본이 2 라 그대로 띄우면
  `PressureRefGen` 이 매 틱 레퍼런스를 덮어써 외부 지령이 안 먹는다.
  기동 로그에 이 줄이 떠야 한다:
  `RefTcpServer [PRESSURE ALL mode]: port 2293 — expects [12 doubles...]`
- **위치 피드백을 쓰지 않는다.** `angle_ctrl.py` 는 이 작업에서 **쓰지 않는다.**
  개루프라야 개체차가 보인다.
- **압력 제어 설정을 건드리지 않는다.** 채널 PID·데드존 표·`i_limit_pct`·레일
  게인은 현재 상태 유지. 여기를 바꾸면 축간 비교의 기준이 흔들린다.
- **90° 위는 정적으로 불안정하다** (각도↑ → 복원토크↓ → 스톱까지 간다).
  `--ang-max 88` 을 반드시 준다. 기본값은 125 다.
- **중단은 측정 스크립트에서 Ctrl-C 한 번.** 양 챔버를 4 kPa/s 로 대기압까지
  램프한다. 런치를 먼저 죽이면 그 램프가 안 돈다.
- **살아 있는 `/pack2` 네임스페이스에 노드를 더 띄우지 않는다.**
  `board/pwm_cmd` 를 둘이 발행하면 지령이 섞인다.
- **시뮬레이션으로 검증하지 않는다.** 코드 수정만 하고 실기 확인은 사용자가 한다.
- **데드존 표는 9분 운전에 3~5 %p 밀린다.** 6축을 1시간 반에 걸쳐 재면 뒤쪽 축이
  다른 조건에서 측정된다. **축 순서를 기록하고, 가능하면 1축을 마지막에 한 번 더
  떠서 드리프트를 재라** — 그 재측정값이 축간 편차의 오차 막대가 된다.

## 쓸모 있는 도구 사용법

```zsh
# 계획만 확인 (하드웨어 안 건드림)
python3 actuator_map.py --axis N --diffs ... --dry-run

# 한 축 마찰 분리
python3 actuator_map.py --axis N --analyze ~/result/actuator_map_<ts>.csv

# 엔코더 보정을 바꾼 뒤, 이미 뜬 맵을 다시 안 뜨고 각도만 고친다
#   두 보정이 모두 선형이라 deg_new = A·deg_old + B 로 가역이다
python3 actuator_map.py --recalib <csv> --old-raw R0,R90 --new-raw R0,R90

# raw 카운트 보기
python3 sensor_monitor.py                 # 런치 띄운 채로 가능
ros2 topic echo /pack2/board/analog_raw   # 토픽 직접
python3 teensy_monitor.py --csv out.csv   # 시리얼 직접 — **런치를 내려야 한다**
```

## 참고 — 이 브랜치가 갈라져 나온 지점

`DMY_mppi_skeleton` 의 `f7df11d`. 거기에는 각도 **피드백** 제어(`angle_ctrl.py`)와
2축 동시 추종까지 들어 있다. **이 브랜치에서는 그 경로를 쓰지 않지만**, 개체차
보정이 끝나면 그쪽으로 돌아가 "보정 후 두 축이 같은 레퍼런스를 얼마나 같이
따라가는가" 로 검증하는 것이 자연스러운 마무리다.

그 브랜치에서 얻은, 여기서도 유효한 사실:

- 압력 루프는 병목이 아니다 — 램프 중 P+ 추종오차 평균 0.11~0.94 kPa, 최대 2.9.
  **단, P+ 목표가 128 kPa 을 넘으면 레일 여유가 모자라 −4.6 kPa 까지 벌어진다.**
- 팔은 `mid(θ) ± f` 밴드 안 **어디에서나 정지**한다. 정특성 측정이 왕복이어야
  하는 이유이고, 마찰이 각 축 정확도의 하한인 이유다.
- 한 방향 스윕만 뜨면 마찰과 중앙값이 섞여 나온다. 반드시 왕복으로 뜬다.
