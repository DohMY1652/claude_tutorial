# 축별 액추에이터 정특성 측정 → 각도 피드백 튜닝 절차

축 하나를 새로 세울 때마다 **통째로 다시 도는** 절차다. 1축 값을 다른 축에
그대로 가져다 쓰면 안 된다 — 아래 튜닝 인자가 거의 전부 **그 축의 마찰 반폭과
플랜트 기울기**에서 크기를 잡은 것이라, 그 두 숫자가 바뀌면 근거가 사라진다.

여기서 쓰는 축 번호는 **사람이 부르는 번호(1~6)** 이고, `board/analog` 인덱스와
yaml 의 `chN` 은 0부터다. 양압 채널 gid = 축−1, 음압 채널 gid = 축+5.

전제: 데드존 표와 채널 PID 는 이미 잡혀 있다 → `데드존측정_튜닝_절차.md`.
여기서는 **압력이 이미 잘 추종된다**는 위에서 출발한다 (실측 램프 중 P+ 추종오차
평균 0.11~0.94 kPa, 최대 2.9 — 압력 루프는 병목이 아니다).

---

## 0. 왜 이 순서인가

각도 제어는 이 한 줄이 전부다. **밸브 모델도 액추에이터 모델도 쓰지 않는다.**

```
차압_ff = mid(각도_ref) + 마찰비율 · f(각도_ref)
차압    = 차압_ff + kvel·d(각도_ref)/dt + kp·e + ki·∫e      (미분항 없음)
P+ = center + 차압/2 ,  P− = center − 차압/2
```

- `mid(θ)` 와 `f(θ)` 는 **정특성 측정에서만** 나온다. 이게 없으면 나머지는
  의미가 없다.
- `f` 는 마찰 반폭이다. 팔은 `mid(θ) ± f` **안 어디에서나 정지**한다 — 즉
  **밴드 안에서 각도는 지령만으로 결정되지 않는다.** 1축 기준 f = 4.86 kPa 이고
  플랜트 기울기 0.93 kPa/° 이므로 각도로 **±5.2°** 다.
- 그래서 정확도는 "피드포워드를 정밀하게" 가 아니라 **"적분이 밴드 가장자리까지
  밀 수 있게"** 로 얻는다. 대신 그 미는 속도에 상한을 걸어 진동을 막는다.
- 순서가 **정특성 → 마찰 분리 → 램프 추종 → 착지 정확도** 인 이유도 같다.
  뒤엣것으로 앞엣것의 오차를 못 고친다.

### 진동을 막는 장치가 어디에 있는지 (중요)

게인이 작아서 안 떠는 게 아니다. **세 군데의 속도 상한**과 **한 가지 구조**다.
축을 옮길 때 이 네 개가 같이 옮겨가야 한다.

| 장치 | 인자 | 무엇을 막나 |
|---|---|---|
| 적분 변화율 상한 | `--i-rate-max` | 적분이 마찰 밴드를 넘는 순간의 stick-slip |
| 출력 변화율 상한 | `--diff-slew`, `--diff-slew-down` | 지령 계단 |
| 목표각 변화율 | `--ang-slew` | 레퍼런스 계단 |
| **마찰 FF 를 거두기만 하고 뒤집지 않는 구조** | (코드) | 밴드 크기의 한계주기 |

마지막 것은 인자가 아니라 코드 구조다. 마찰 피드포워드는 목표를 지난 뒤에는
0(밴드 중앙)으로 흘려보내기만 하고 **절대 반대 부호로 가지 않는다.** 뒤집게
두면 목표를 지날 때마다 전폭 반전(2f ≈ 9.7 kPa)이 걸려 밴드 크기의 한계주기가
생긴다.

## 3. 정특성 측정 (터미널 3)

### 원리

각 (P+, P−) 조합에서 팔이 **멈추는 각도**를 잰다. 정지 상태에서는 액추에이터
토크와 중력 토크가 균형이므로 각도 하나로 토크를 역산할 수 있다:

```
tau_act(P+, P−) = m·g·L·sin(θ)     [N·m]
F_act           = tau_act / r_reel [N]
```

즉 산출물은 각도표가 아니라 **액추에이터 힘 모델**이다.

두 가지가 이 측정의 천장을 정한다:
- **90° 위는 정적 평형이 불안정하다** (각도↑ → 복원토크↓ → 스톱까지 간다).
  그래서 85° 에서 멈춘다. 그 위를 쓰려면 위치 피드백이 있어야 한다.
- **한 방향 스윕은 구간으로만 나온다.** 왕복해서 올림/내림 중점으로 마찰을
  분리해야 `mid` 와 `f` 가 따로 나온다.

### 명령

```zsh
cd ~/claude_tutorial/src/can_powerpack/scripts
source /opt/ros/humble/setup.zsh && source ~/claude_tutorial/install/setup.zsh

# 계획만 확인 (하드웨어 안 건드림)
python3 actuator_map.py --axis N --preset lift90 --ang-max 88 --dry-run

# 실제 측정 — 약 14분
python3 actuator_map.py --axis N --preset lift90 --ang-max 88
```

### ★ `--ang-max 88` 은 새 축에서 필수다

`--preset lift90` 의 차압 목록은 **1축 실측(차압 40 kPa → 46.9°)** 하나에서
역산한 값이다. 코드의 강성 상수가 그 점에 박혀 있다.

```
목표 각도    0   10   20   30   40   50   55   60   65   70   74   78   81   83   85
필요 차압  0.0  9.5 18.7 27.4 35.2 42.0 44.9 47.4 49.6 51.5 52.7 53.6 54.1 54.4 54.6
```

새 축이 1축보다 **무르면 같은 차압에서 더 올라간다.** 그런데 `--ang-max` 기본값이
**125°** 라 90° 를 넘어 불안정 구간에 들어가도 안 멈춘다. 88 로 잡으면 85° 목표에
3° 여유를 두고 넘어가기 전에 끊긴다.

끊겨도 손해가 없다 — 그때까지의 CSV 행으로 강성을 계산해 `--diffs` 로 비율을
조정해 다시 돌리면 된다.

### 중단이 필요하면

터미널 3 에서 **Ctrl-C 한 번**. 스크립트가 양 챔버를 `--release-slew`(4 kPa/s)로
대기압까지 **램프로** 내린다 — 끊지 않는다. 터미널 1 을 먼저 죽이면 그 램프가
안 돌아가니 **순서를 지킨다.**

## 4. 마찰 분리

```zsh
python3 actuator_map.py --axis N --analyze ~/result/actuator_map_<타임스탬프>.csv
```

여기서 나오는 두 숫자가 이후 전부의 기준이다:

| 숫자 | 1축 값 | 어디에 쓰나 |
|---|---|---|
| **마찰 반폭 f** | 4.86 kPa | `--i-rate-max`, `--fric-hold-band`, `--kvel-down`, 적분 데드밴드 |
| **플랜트 기울기** d(차압)/dθ | 0.93 kPa/° | 위 값들을 각도로 환산할 때 |

참고로 1축에서 토크 이득은 차압이 커질수록 0.046 → 0.024~0.035 N·m/kPa 로
떨어졌고, 마찰 ±0.143 N·m 은 측정 구간의 8.7 % 였다.

### 새 축 값이 다르면 — **스크립트가 자동으로 환산한다**

게인이 전부 kPa 단위라 기울기가 다른 축에 그대로 못 간다. `angle_ctrl.py` 는
`--gain-ref-slope`(기본 0.88 = 1축 실측) 에서 잰 값으로 인자를 해석하고, 축마다
기울기 비를 곱한다. **직접 계산할 필요가 없다.** 환산 대상:

```
kp · ki · --kvel-down · --i-rate-max · --diff-slew · --diff-slew-down
```

각도로 본 거동(°/s, °)이 축에 무관하게 같아진다. 기동 출력에 축별 환산값과
`적분이 낼 수 있는 각속도`, `램프가 먹는 차압 / 올림 여유` 가 찍히므로 거기서
확인한다. **올림 여유가 +1 kPa/s 아래면 그 축은 램프를 못 따라간다** (6-1 참고).

환산하지 않는 것: `--fric-hold-band`·`--tol` 은 원래 각도 단위이고,
`--diff-max`·`--max-rate` 는 안전 한계다. `--i-deadband` 는 f 와 기울기에서
자동으로 나온다.

### 실측값

| | 1축 | 2축 |
|---|---|---|
| 마찰 반폭 f | 4.31 kPa | 3.82 kPa |
| 플랜트 기울기 | 0.88 kPa/° | **1.26 kPa/°** |
| 환산계수 | ×1.00 | **×1.43** |
| 맵이 덮는 각도 | 21.1~84.6° | **14.5~47.0°** |

2축은 1축보다 43 % 뻣뻣하고, 같은 차압에서 절반밖에 못 올라간다. 2축의 표가
47° 에서 끝나는 것은 preset 이 1축 기준이라 차압 54.6 kPa 에서 멈췄기 때문이다 —
더 위를 쓰려면 `--diffs` 로 60~80 kPa 까지 늘려 다시 떠야 한다.

## 4-1. 여러 축을 **같은 레퍼런스로 같은 타이밍에**

```zsh
python3 angle_ctrl.py --axes 1,2 \
    --map ~/result/<1축 csv들, 쉼표> \
    --map ~/result/<2축 csv> \
    --targets 25,35,45,35,25 --ang-max 45
```

- `--map` 을 **축 순서대로 하나씩** 준다. 한 축에 CSV 가 여럿이면 그 안에서 쉼표.
  축마다 맵이 다르므로 하나만 주면 거부한다.
- **램프(목표각과 그 슬루)는 하나만 만들어 공유한다.** 맵·마찰·적분·게인만 축마다
  따로 간다. 이것이 "같은 타이밍" 의 의미다.
- 시작 각도는 축들의 **평균**에서 출발한다. 한 축에 맞추면 나머지가 첫 구간에서
  계단을 받는다. 시작 각도가 2° 넘게 벌어져 있으면 경고한다.
- **도착은 모든 축이 `--tol` 안에 들어와야** 인정한다.
- **안전은 축마다 본다. 한 축이라도 걸리면 전체가 중단되고 모든 축이 대기압으로
  램프된다.**
- 목표 범위는 기동 출력의 `공통으로 덮는 각도` 안에 둔다. 밖이면 어느 한 축의
  표 끝값으로 고정돼 피드포워드가 틀어진다.

CSV 는 축별로 `_ax1` / `_ax2` 접미사가 붙는다 (축이 하나면 예전과 같은 모양).

`--targets` 를 생략하면 대화형(타이핑)이다. 기동 로그에서 볼 것:

- 피드포워드 표 (각도별 중앙 / 올릴 때 / 내릴 때)
- `적분: 데드밴드 밖에서만, 슬루 포화 중 정지, 변화율 ≤ ...`

### 첫 런은 좁게

```zsh
python3 angle_ctrl.py --axis N --map <csv> --targets 30,45,30 --ang-max 60
```

진동 가드(`--osc-flips 6` / `--osc-window 6`)가 한 번도 안 걸리는지 먼저 본다.
걸리면 **범위를 넓히기 전에** 아래 8절로 간다.

### 결과 보는 법

`~/result/angle_ctrl_<타임스탬프>_summary.csv`:

```
idx,ang_tgt,arrived,arrive_s,ang_mean,ang_std,err_mean,err_end,overshoot,diff_final,tau_Nm
```

- **`err_end`** (유지구간 뒤 1/3 평균 − 목표) 가 정확도 판정값이다.
- `err_mean` 은 유지구간 **전체** 평균이라 적분이 잔류를 닫는 과도가 섞여 있다.
  둘이 크게 다르면 "수렴이 아직 안 끝난 것" 이고 시간 부족이다.
- `ang_std` 가 0.5 를 넘으면 유지 중 움직이고 있다는 뜻 — 진동을 의심한다.

## 6. 튜닝 — 증상 → 원인 → 인자

**순서대로 본다.** 램프 추종이 안 맞는 상태에서 착지 인자를 건드리면 안 된다.

### 6-1. 램프 추종 (지연)

먼저 **어느 방향이 문제인지**와 **율 제한에 닿았는지**를 가른다. 로그에서
`diff_cmd` 의 상승률이 `--diff-slew` 값과 정확히 같으면 율 제한이다.

| 증상 | 원인 | 고칠 것 |
|---|---|---|
| **올림이 램프보다 느리다** (지연 +, 각속도 < 램프) | `--diff-slew` 병목 | `--diff-slew` ↑ |
| **올림이 램프보다 빠르다** (지연 −, 각속도 > 램프) | 밀어주는 양 과다 | `--fric-ff` ↓, 그다음 `--diff-slew` ↓ |
| **내림이 느린데 율 제한에 안 닿는다** | 플랜트(부피 외란) | `--kvel-down` ↑ |
| **내림이 율 제한에 닿는다** | `--diff-slew-down` 병목 | `--diff-slew-down` ↑ |

**올림의 율 제한이 왜 그렇게 아슬아슬한가**: 램프 자체가
`플랜트기울기 × ang_slew` 를 먹는다. 1축 기준 `0.93 × 1.49 = 1.39 kPa/s` 다.
`--diff-slew 1.5` 면 지연을 따라잡는 데 쓸 여유가 **0.11 kPa/s** 뿐이라 한 번
벌어진 차이를 영영 못 메운다. 반대로 2.5 로 열어 주면 자연 속도가 램프를 넘어
(1.74 vs 1.49 °/s) 오버슛으로 돌아온다. **그 사이가 적정 구간이다.**

**내림은 항상 올림보다 든다.** 내려오면서 양압 챔버 부피가 줄고(P+ 상승) 음압
챔버가 늘어(P− 하강) 외란이 **늘 지령을 거스른다.** 그래서 `--fric-ff-down`
(1.0 = 측정 마찰 전폭) 과 `--kvel-down` 이 올림보다 크다.

`--kvel-down` 크기 정하는 법 — 실측에서 역산한다:
```
지령 부족  = 지연[°] × 플랜트기울기
kp 기여분  = kp × 지연[°]
kvel 상한  = (지령 부족 − kp 기여분) / 램프속도[°/s]
1축: (4.3×0.93 − 0.3×4.3) / 1.49 = 1.8   → 1.5 채택
```
레퍼런스만의 함수라 측정을 안 쓴다. **구조적으로 진동할 수 없다.**

### 6-2. 착지 (오버슛 / 못 미침)

| 증상 | 고칠 것 |
|---|---|
| 내림 `err_end` **양수** (목표 **위**에서 멈춤) | `--fric-hold-band` ↓ |
| 내림 `err_end` **음수** (지나침) | `--fric-hold-band` ↑ |
| 올림 오버슛 | `--fric-ff` ↓ (6-1 의 램프 속도부터 확인) |

`--fric-hold-band` 는 "가던 방향으로 이만큼 남았으면 아직 이동 중으로 본다" 이다.
회수에 지령이 f 만큼 움직여야 하고 그동안 팔이 계속 가므로 — **작으면 지나치고
크면 못 미친다.** 1축 이력: 1.5 → +1.47/+1.24, 0.5 → +0.79/+0.55, 0.3 채택.

### 6-3. 정상상태 오차 (도착은 하는데 1° 가 안 지워짐)

거의 항상 **적분이 마찰 밴드 안에서 죽어 있는 것**이다. 확인법: 로그의
`diff_i` 가 구간마다 **같은 값에 얼어 있으면** 데드밴드가 삼킨 것이다.

| 인자 | 역할 |
|---|---|
| `--i-deadband-frac` (0.05 → f 의 5 %) | 넓히면 그 안의 오차를 **아무것도** 못 지운다 |
| `--ki` (0.3) | 데드밴드 밖 적분 속도 |
| `--i-rate-max` (0.4) | **진동을 막는 장치가 여기다** |

`kp`(0.3 kPa/°) 는 플랜트 기울기(0.93 kPa/°) 보다 작으므로 **P 항만으로는 원리적으로
오차를 닫을 수 없다.** 반드시 적분이 해야 한다. 그래서 데드밴드를 좁게 두고,
안전은 `--i-rate-max` 로 따로 건다.

유지 중 `ang_std` 가 커지거나 목표 주변을 왕복하면 **`--i-rate-max` 를 먼저 내린다**
(0.4 → 0.25). 데드밴드는 더 넓히지 않는다 — 그러면 6-3 이 다시 생긴다.

## 8. 진동이 나면

액추에이터가 깨지는 게 최악이므로 **범위를 넓히기 전에** 여기서 끝낸다.
순서대로 하나씩, 한 번에 하나만 바꾼다.

1. `--i-rate-max` 0.4 → **0.25** → 0.15
2. `--ang-slew` 1.5 → **1.0**
3. `--diff-slew` / `--diff-slew-down` 을 각각 **20 % 씩** 내린다
4. `--fric-ff-down` 1.0 → **0.8** (밀어주는 양 자체를 줄인다)

**데드밴드를 넓혀서 진동을 잡지 않는다.** 잡히긴 하지만 정상상태 오차가 그만큼
영구히 남는다 (실측 +3.3° 잔류). 진동은 **속도**로 잡고 오차는 **적분**으로 지운다.

## 9. 흔한 함정

- **`control_mode:=0` 을 빼먹는다.** yaml 기본이 2 라 `PressureRefGen` 이 매 틱
  레퍼런스를 덮어써서 아무 반응이 없다. 증상이 "밸브가 안 움직인다" 로 나온다.
- **양압 목표가 128 kPa 을 넘는데 −4 kPa 씩 모자란다.** 채널 적분이 상한에
  박힌 것이다. 로그의 `i_term_gid<N>` 이 `i_limit_pct` 값에 정확히 붙어 있고
  `gain_scale` 도 2.00 이면 확정이다. 근본 원인은 레일 여유 부족 —
  P+ 142 에 레일 160 이면 차압이 19 kPa 뿐이라 같은 개도로 흐르는 유량이 적다.
  `rail_ref.py --hold-ref 200 30` 으로 레일을 올려서 확인한다.
- **1축 튜닝값을 새 축에 그대로 쓴다.** 거의 전부가 그 축의 f 와 기울기에서 나온
  값이다. 4절의 비율 환산을 거친다.
- **`--preset lift90` 을 `--ang-max` 기본값으로 돌린다.** 3절 참고.
- **살아 있는 `/pack2` 네임스페이스에 노드를 하나 더 띄운다.** `board/pwm_cmd` 를
  둘이 발행하게 되어 지령이 섞인다. 런치는 하나만 띄운다.
- **터미널 1 을 먼저 죽인다.** 측정 스크립트의 대기압 램프가 안 돌아간다.
- **`err_mean` 으로 정확도를 판정한다.** `err_end` 를 본다 (5절).
- **유지 시간이 모자란 것을 오차로 오인한다.** `err_mean` 과 `err_end` 가 크게
  다르면 `--settle-hold` 를 15 로 올려 **시간 부족인지 바닥인지부터 가른다.**
