## 확인한 사실

- 두 중단 모두 커널에서 `usb 3-7: USB disconnect` 후 Teensyduino 장치
  (serial 16956980)가 새 device number로 다시 등록됐다.
- CAN 브리지는 101/102 ms 엔코더 무수신을 감지하고 대체 각도 180°를 발행했다.
  기록의 180°는 실제 기계적 각도 초과의 증거가 아니라 페일세이프 경로와 일치한다.
- 첫 브리지 로그: `~/.ros/log/can_bridge_node_18552_1791261695182.log`.
  두 번째: `~/.ros/log/can_bridge_node_20560_1791266086900.log`.
- USB 재등장 뒤 `Teensy 열림`과 `포트를 닫고 재연결`이 수 ms 간격으로 반복됐다.
- 조사 시 `/sys/bus/usb/devices/3-7/power/control=on`, `runtime_status=active`,
  `runtime_suspended_time=0`이었다. 조사 시점 상태이며 과거 모든 전원 상태를 증명하지는 않는다.
- 두 번째 실행의 종료 복귀는 BrokenPipeError로 실패했다. 첫 실행도 TCP 목표 송신만
  완료됐으며 최종 압력 표본은 11초 이상 오래됐다. 실측 대기압 복귀가 확인된 것이 아니다.

## 수정한 소프트웨어 결함

기존 `teensy_seen_`와 `teensy_last_ns_`는 이전 연결의 값을 유지한다.
새 포트를 열고 `r`(stream 시작)을 보낸 직후, 오래된 `last_ns` 때문에 watchdog이
포트를 닫으며 `x`(stream 정지)를 보냈다. 첫 200 Hz 프레임을 기다리기 전에
다시 닫는 경로가 있어 복구를 방해한다.

`received_since_open`을 추가해 현재 연결에서 유효 프레임을 받았는지 구분했다.
새 연결은 기존의 첫 프레임 제한(2초)을 적용하고, 이전 timestamp만으로 즉시 닫지 않는다.

변경하지 않은 것:

- 엔코더 정상 판정은 여전히 실제 유효 프레임 수신 후에만 이뤄진다.
- last receive timestamp를 open 시각으로 조작하지 않는다.
- 100 ms watchdog, stale/180° 표시, 3초 안전상태 + 1.5초 종료 시한 유지.
- 안전상태 latch를 해제하지 않는다. 이미 latch된 브리지는 수신이 복구돼도 재기동 필요.
- 압력 PID·데드존·레일 튜닝 및 압력 프로파일 불변.
- 실행기는 180° 수신 시 여전히 중단한다. 자동으로 시험을 재개하지 않는다.

정적 구조 회귀 검사만 추가했다. 가상 직렬 장치/시뮬레이터로 실기 제어 코드를
실행하지 않았고, 실기 재연결 동작 검증도 수행하지 않았다.

검증 결과: 오프라인·정적 검사 58개 통과. 워크스페이스 루트에서 Humble을 source하고
`colcon build --packages-up-to can_powerpack --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release`
수행 결과 qpoases_vendor와 can_powerpack 두 패키지 빌드 성공(약 44초).
기존 워크스페이스 underlay 중복 경고는 있었다. 실행 중인 노드는 재시작하지 않았다.

## 아직 해결됐다고 할 수 없는 부분

이 수정은 **USB 연결 해제 이후의 복구 결함**을 고친다. 최초 USB disconnect를
막는 수정은 아니다. 케이블·접점·전원·보드 리셋 중 어느 것이 원인인지는 미확정이다.
저장소의 `angle_sensor.ino`는 500 Hz 텍스트 형식으로, 실제 Teensy 200 Hz 바이너리
스트림 펌웨어와 다르므로 이를 현재 펌웨어라고 가정해 수정/업로드하지 않는다.

반복 측정을 다시 시작하기 전에 USB 연결·전원 경로의 현장 점검이 필요하다.
수정 적용은 재빌드 후, 안전한 대기압 상태에서 사용자가 브리지를 재기동해야 한다.
재기동만으로 최초 USB 문제가 해결됐다고 판단하거나 watchdog을 늘리지 않는다.
