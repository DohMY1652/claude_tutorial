## 0. 결론

**두 개체는 각도 눈금이 같고, 2번이 전 구간에서 일정하게 +3.4° 높다.**

```
θ₂ = 1.0042 · θ₁ + 3.41°        잔차 sd 0.60°   (n=215)
```

`b = 1.0042` 는 **이득이 0.4 % 이내로 같다**는 뜻이고, 차이는 전부 영점이다.
힘을 내는 능력(효율비·포화·마찰)은 세 지표 모두 두 개체가 거의 같다.

> ⚠ **이 +3.4° 가 진짜 개체차인지 엔코더 영점 보정 차이인지는 이 데이터로 못 가른다.**
> 순수한 각도 오프셋은 `raw_0deg` 를 767 카운트 다르게 잡았을 때 나오는 것과
> **구별이 안 된다.** §4 의 확인을 먼저 할 것.

## 1. 짝비교 — 이게 이번 비교의 핵심 숫자

| 그 산포 (sd) | **0.60°** |
| 범위 | +2.17 ~ +5.19° |

### ★ 왜 산포가 0.60° 밖에 안 되나 — 같은 seed 로 돌린 덕이다

개별 재현성은 1번 sd 2.86° / 2번 3.19° 다. 그런데 **짝 차이의 산포는 0.60°** 다.
두 런이 **완전히 같은 984 단 계획**으로 돌았기 때문에, 각 동작점에 도달한 이력이
양쪽에서 같았고 마찰 띠 안의 위치가 **차감될 때 상쇄된** 것이다.

> 계획을 다르게 잡았으면 3° 잡음 속에서 3.6° 차이를 찾아야 했다. **`--seed` 를
> 고정하는 규칙이 이 비교를 가능하게 했다.**

## 4. ★ 다음에 할 것 — +3.4° 의 정체를 가른다

순수한 각도 오프셋은 두 가지가 똑같이 만든다:

| 원인 | 어떻게 확인하나 |
|---|---|
| (a) 2번의 건 장력/조립이 달라 실제로 3.4° 높이 쉰다 | 아래 확인에서 두 개체의 **0° 원점 raw 가 같은 물리 위치**임이 확인되면 이쪽 |
| (b) `raw_0deg` 를 **767 카운트** 다르게 잡았다 | 확인에서 어긋나면 이쪽 |

**눈금은 이미 검증됐다.** `b = 1.0042` 이므로 두 보정의 span(1번 19660 / 2번 20255,
3.0 % 차)은 서로 **모순이 없다** — 센서 이득이 실제로 3 % 다르고 보정이 그것을
제대로 잡아 준 것이다. 남은 것은 영점뿐이다.

### 확인 방법

팔을 **같은 물리적 기준**(0° 하드스톱 등)에 대고 `sensor_monitor.py --source direct`
로 raw 를 읽는다. 두 개체를 각각 달았을 때:

- 그 위치에서 **둘 다 0.00° 로 읽히면** → 보정은 맞고 **+3.4° 는 진짜 개체차**다
  (2번의 탄성 프리로드가 팔을 그만큼 더 들고 있다).
- **한쪽이 3.4° 쯤 어긋나면** → 보정 오차다. 그 개체의 `raw_0deg` 를 고치고,
  이미 뜬 데이터는 `actuator_map.py --recalib` 로 환산하면 된다 (두 보정 모두
  선형이라 가역이다).

> 이 확인을 하기 전에는 **"2번이 3.4° 더 센 개체다" 라고 결론내면 안 된다.**
> `개체차_보정_인수인계.md` 의 "엔코더 보정이 틀리면 개체차 측정은 통째로
> 무의미하다" 가 바로 이 상황이다.
