## 1. 지금 설정 (1축 기준)

### 1-1. 새로 만든 인자 다섯

기존 PID 에 없던 것들이다. 전부 `PressureCtrl` 안이고 yaml 로 켜고 끈다.

| 인자 | 값 | 무엇을 막나 |
|---|---:|---|
| `i_lead_s` | 방향별 0.3~0.8 | **접근 중 적분 와인드업.** 오차가 아니라 "이 시간 뒤에 남아 있을 오차" 로 적분한다: `e_pred = e + i_lead_s·de/dt` (de/dt 는 **측정에서만**). 플랜트가 멈춰 있으면 `de/dt = 0` 이라 그대로 적분하므로 **교착이 없다** |
| `i_dp_min_kpa` | 3.0 | **레일이 비었는데 도는 적분.** micro(레일 공급) 방향에서 차압이 이보다 작으면 적분 정지. atm 은 대기가 상대라 마르지 않으므로 **걸지 않는다** (걸면 대기압 목표에서 영영 못 내려간다) |
| `i_opp_leak_tau_s` | 0.3 | **램프 진입에서 안 지워지는 반대 부호 적분.** 정착 구간 밖에서 적분이 필요한 방향과 반대면 이 시정수로 흘린다. `i_reset_on_step` 은 지령이 **점프**할 때만 보므로 램프에는 안 걸린다 |
| `atm_margin_kpa` | 0.5 | **챔버가 대기압 반대편으로 갔을 때의 밸브 선택.** 양압이 대기압 아래(또는 음압이 위)면 압력을 올리는 밸브는 micro 가 아니라 **atm** 이다. 넘어가는 순간 적분도 버린다. 단 **atm 이 목표까지 갈 수 있을 때만** 적용한다 (목표가 대기압 너머면 레일이 맞다) |
| `atm_boost_pct` | 20.0 | **그 구간에서 여는 양.** 위 선택이 맞아도 여는 양이 모자라면 회복이 한없이 느리다 — 오차와 구동 차압이 **같은 수**라 P 항과 유량이 같이 0 으로 수렴하기 때문이다. 목표가 대기압이거나 **그 너머**면 atm 을 최소 이만큼 연다. 부스트 중에는 적분을 멈춘다 |

그리고 `kd` 를 **오차 미분에서 측정 미분으로** 바꿨다 (`d_tau_s` 로 거른다).
오차로 미분하면 목표 계단이 그대로 미분돼 첫 틱에 `d_term` 이 330 %p 까지 튄다.

### 1-2. 스칼라

```yaml
ChannelPID:
  kp: 0.6      kp_far: 0.6      kp_break_kpa: 3.0
  ki: 2.0      ki_far: 1.0      kd: 0.03
  i_limit_pct: 20.0             i_deadband_kpa: 0.0    band_kpa: 0.0
  i_reset_on_step_kpa: 1.0
  gain_dp_ref_kpa: 60.0         gain_scale_min: 0.6    gain_scale_max: 2.0
  kv: 1.0      ref_rate_tau_s: 0.3     ff_limit_pct: 15.0
  i_lead_s: 0.3                 i_dp_min_kpa: 3.0
  i_opp_leak_tau_s: 0.3         atm_margin_kpa: 0.5    d_tau_s: 0.02
```

### 1-3. 방향별 오버라이드

```yaml
ChannelPID.pos.up:    kp_far 1.2                              # i_lead 는 전역 0.3
ChannelPID.pos.down:  kp 1.5 · kp_far 1.8 · kv 1.5 · i_lead_s 0.8
ChannelPID.neg.down:  i_lead_s 0.5
channel_config.ch6.pid.up:  ki 3.0 · kp 1.6 · kp_far 1.6 · i_lead_s 0.6
```

**실효 `i_lead_s`: 양압 올림 0.3 · 양압 내림 0.8 · 음압 올림 0.6 · 음압 내림 0.5**

### 1-4. 데드존 여유 — **음수다**

```yaml
channel_config.ch0.deadzone:  margin_micro_pct −3.0 · margin_atm_pct −4.5
channel_config.ch6.deadzone:  margin_micro_pct −3.0 · margin_atm_pct −4.5
valve_deadzone.margin_pct: 1.0        # 나머지 축은 여전히 +1.0
```

`실제 지령 = 표(차압) − margin` 이므로 **음수면 표 위로** 바이어스가 올라간다.
이유는 3-2 에 있다. **이 장비에서 음수 margin 은 이번이 처음이다.**

## 2. 튜닝 순서 — 증상 → 원인 → 손잡이

**반드시 위에서부터 본다.** 아래 것으로 위 것을 못 고친다.

### 2-0. 먼저 조건부터 확인한다 (3절)

게인을 만지기 전에 **액추에이터 장착 여부 · 레일 실측값 · 데드존 표의 측정 조건**
세 가지를 확인한다. 여기가 틀리면 아무리 튜닝해도 소용없다.

### 2-1. 한계주기(밸브가 번갈아 열림)

로그에서 `micro` 와 `atm` 의 **크래킹 교차 횟수가 같으면** 한계주기다.

| 원인 | 손잡이 |
|---|---|
| 챔버 부피가 작다 (액추에이터 미장착) | 팔을 단다. 게인으로 못 고친다 |
| 레일이 챔버에 끌려 무너진다 | 레일을 올리거나 계단 크기를 줄인다 |
| margin 이 과하게 음수 | `margin_*_pct` 를 0 쪽으로 |

`gain_scale_max` 를 낮춰 잡으려는 시도는 **역효과였다** (3/3 악화, 3-6 참조).

### 2-2. 오버슛

| 증상 | 손잡이 |
|---|---|
| 계단 뒤 크게 넘어간다, 적분이 상한(20)에 붙는다 | 그 방향 `i_lead_s` ↑ |
| 레일이 무너진 동안 적분이 찼다 | `i_dp_min_kpa` (이미 3.0) |
| 램프 진입 뒤 반대로 밀린다 | `i_opp_leak_tau_s` (이미 0.3) |
| 위 셋을 다 해도 남는다 | 그 방향 `kp_far` ↓ |

`i_lead_s` 는 **움직이는 동안만** 작동하므로 정착·속도를 안 건드린다. 오버슛
전용 손잡이로 제일 먼저 쓴다. 단 방향마다 최적값이 다르다 — 2-5 참조.

### 2-3. 수렴이 느리다 (마지막 1~3 kPa)

**먼저 개도를 본다.** `pwm − dz` 가 크래킹 위 몇 %p 인지.

```
개도 0~3 %p   → 유량이 사실상 0 (무릎 아래)
개도 4.5~6    → 유량이 살아나는 무릎
개도 7 이상   → 정상 유량
```

| 개도 | 진단 | 손잡이 |
|---|---|---|
| 무릎 아래에서 굳어 있다 | 바이어스가 낮다 | `margin_*_pct` 를 음수로 (3-2) |
| 무릎 위인데 느리다 | 팔을 들고 있는 중이다 | **게인으로 못 고친다** (3-3) |
| 반대 부호 적분에 잡혀 있다 | 램프 진입 유물 | `i_opp_leak_tau_s` ↓ |

`kp` 를 올려 해결하려는 시도는 **두 번 다 실패했다** (3-3, 3-6).

### 2-4. 정상상태에서 흔들린다

**밸브 토글 수를 먼저 본다.**

- 토글이 있다 → 한계주기다 (2-1)
- **토글이 0 인데 압력이 흔들린다 → 팔이다.** 각도 p-p 를 같이 보면 바로 안다.
  팔이 마찰 밴드 안에서 stick-slip 으로 움직이면 챔버 부피가 변해 압력이 흔들린다.
  실측: 유지 4.2 s 동안 팔이 **13~14° 를 튀어** 압력이 3.6~4.0 kPa p-p 로 흔들렸다.
  같은 런에서 팔이 조용한 구간(각도 p-p 0.05~0.2°)은 압력 p-p 가 0.13~0.45 다.
  **제어 실패가 아니다.**

### 2-5. 방향마다 따로 잡는다

네 방향의 플랜트가 전부 다르다. **한 방향에서 좋은 값이 다른 방향에서 나쁘다.**

실측 예 — `i_lead_s` 를 0.3 → 0.6 으로 올렸을 때:

| 방향 | 결과 |
|---|---|
| 음압 올림 | 오버슛 최대 **+4.26 → +1.26**, 속도도 0.54 → 0.40 s. **채택** |
| 양압 올림 | 오버슛 +1.01 → +0.69 (0.32 이득), ±0.5 **1.18 → 1.47 s** (0.29 s 손해). **되돌림** |

충전은 팔을 들어올리는 일이라 접근이 느려 `de/dt` 가 작고, 게이팅을 세게 걸면
정작 필요한 적분까지 못 쌓는다. 배기·음압과 사정이 다르다.

## 3. 함정 — 여기서 런을 버렸다

### 3-1. ★ 액추에이터 장착 여부가 게인을 통째로 바꾼다

**같은 게인으로 팔이 있을 때와 없을 때를 비교하면:**

| 목표 | 팔 있음 (각도 88.9° 이동) | 팔 없음 (각도 0.1°) |
|---|---:|---:|
| 131.3 | 0.56 kPa p-p | **22.35 kPa ★발산** |
| 141.3 | 0.69 | **20.03 ★** |
| 151.3 | 0.57 | **19.64 ★** |

팔을 떼면 챔버 부피가 10배 이상 작아진다 (`actuator_connected: False` 일 때
컨트롤러도 50 mL 로 본다). `dP/dt = 유량/부피` 이므로 **플랜트 이득이 10배**다.
팔이 달린 조건에서 잡은 게인은 부피가 사라지면 그대로 발산한다.

> **확인법**: 로그의 `enc_bd17_deg` 범위를 본다. 이동이 5° 미만이면 팔이 없거나
> 건이 빠진 것이다. `angle_deg_axis0` 은 control_mode 0 에서 예전에 0 이었다(3-5).

### 3-2. ★ 데드존 표는 "유량이 시작되는 점" 이지 "쓸 만한 점" 이 아니다

`valve_deadzone.py` 는 **팔을 떼고 작은 부피에서 `0.40 kPa/s` 문턱**으로 잰다.
팔이 붙으면 챔버 부피가 10배라 같은 유량이 1/10 의 `dP/dt` 밖에 못 낸다.

실측 (액추에이터 장착, 차압 통제, 세 런 합산):

| 밸브 | 크래킹 위 0~3 %p | 무릎 | 무릎 위 |
|---|---:|---:|---|
| 양압 micro | 0.3~0.5 kPa/s | **+4.5 %p** | 5~7 → 2.9, 7~10 → 8.3 |
| 양압 atm | 0.2~0.4 | **+6.0** | — |
| 음압 micro | 0.2~0.5 | **+4.5** | 5~7 → 6.8, 7~10 → 29 |
| 음압 atm | 0.5~0.7 | **+6.0** | 5~7 → 1.6 |

**크래킹 위 3~4 %p 까지는 유량이 사실상 0 이다.** 그런데 컨트롤러는 목표 근처에서
+3.1~4.4 %p 에 머문다 — 전부 무릎 아래다. 그래서 마지막 3 kPa 를 기어갔다.

**그래서 `margin` 을 음수로 둔다.** 무릎 **바로 아래**에 바이어스를 두면,
목표에 앉아 있을 때(`u_pid ≈ 0`)는 유량이 거의 0 이라 안 새고, 오차가 1~2 kPa 만
생겨도 곧바로 무릎을 넘어 유량이 확 난다.

결과: ±0.5 kPa 도달이 **양압 1.64 → 1.18 s, 음압 1.53 → 0.56 s**.

> **왜 데드존을 다시 잰 뒤 느려졌나** — 옛 표는 실제 크래킹보다 2.4 %p **높았고**,
> 그 오차가 우연히 이 간극을 메우고 있었다. 표를 정확히 고치자 그 보정이 사라졌다.
> "표를 고쳤는데 느려졌다" 는 표가 틀린 게 아니라 **정의가 다른 것**이다.

### 3-3. ★ 마지막 3 kPa 는 "팔을 드는 시간" 이다

목표 근처에서 **압력 변화율과 각속도가 1:1** 이다:

```
오차 3~4 : 압력 3.63 kPa/s · 각속도 +3.57 °/s
오차 1~2 : 압력 2.88        · 각속도 +2.95
오차 0.5~1: 압력 2.34       · 각속도 +2.32
```

1축 플랜트 기울기가 0.86 kPa/° 이니 정확히 맞물린다. 팔은 그 차압이 만드는
토크로 평형을 잡으므로 **챔버 압력을 팔의 무게가 고정한다.** 기체를 더 넣으면
압력이 오르는 게 아니라 팔이 올라가며 챔버가 커져 흡수한다.

`kp` 를 0.6 → 1.2 로 올려 봤더니 개도는 +3.5 → +4.4 로 늘었는데 ±0.5 도달이
**1.64 → 2.06 s 로 되레 느려졌다** (레일·차압·챔버압 동일 조건). 되돌렸다.

**단, 무릎 아래에서는 이야기가 다르다.** 3-2 의 margin 을 고친 뒤에는 개도가
무릎을 넘어 유량이 제대로 나온다. "게인이 안 듣는다" 는 **무릎 아래일 때의 현상**이지
언제나 그런 게 아니다. 순서는 **margin(무릎) 먼저 → 그 다음 게인**이다.

### 3-4. 6단 게인 계층 — `channel_config.chN.pid` 가 제일 세다

```
1 ChannelPID.*                        전 채널·전 방향
2 ChannelPID.{up,down}.*              방향별
3 ChannelPID.{pos,neg}.*              측별
4 ChannelPID.{pos,neg}.{up,down}.*    측별·방향별
5 channel_config.chN.pid.*            채널별
6 channel_config.chN.pid.{up,down}.*  채널별·방향별   ← 제일 세다
```

`channel_config.ch6.pid.up` 에 `ki 3.0 · kp 1.6 · kp_far 1.6` 이 박혀 있어서,
`ChannelPID.neg.up` 에 적은 값이 **조용히 무시됐다.** 고치기 전에 반드시 확인한다:

```zsh

d=yaml.safe_load(open('src/can_powerpack/config/powerpack_config.yaml',encoding='utf-8'))['/pack2/pp_controller']['ros__parameters']
print('ChannelPID.pos =', d['ChannelPID'].get('pos'))
print('ChannelPID.neg =', d['ChannelPID'].get('neg'))
for ch in ('ch0','ch6'): print(ch, (d['channel_config'].get(ch) or {}).get('pid'))
"
```

### 3-5. 로그의 각도 열

- `control_mode: 0` 에서는 `position_dbg` 도 `refgen_dbg` 도 발행되지 않는다.
  예전에는 폴백이 없어 **`angle_deg_axisN` 이 전 구간 0** 이었고, 진짜 각도는
  `board/analog` 에서 와서 **`enc_bd{17+a}_deg`** 라는 옛 CAN 시절 이름에만 들어갔다.
  20260916 에 `pp_logger.py` 에 폴백을 넣어 지금은 두 열이 같은 값이다.
- **기동 직후 약 4초는 버린다.** Teensy 스트리밍 전이라 raw < 1000 이 되어
  각도가 **121~129°** 로 읽힌다 (죽은 센서와 같은 값이다).

### 3-6. `gain_scale` 을 낮춰 진동을 잡으려 하지 말 것

레일이 무너져 `dp_micro` 가 작아지면 `gain_scale = 60/dp` 가 상한으로 튄다.
"그러니 상한을 낮추자" 고 2.0 → 1.2 로 해 봤더니 **3회 전부 나빠졌다**:

| | gs_max 2.0 | gs_max 1.2 |
|---|---|---|
| 45 kPa 계단 오버슛 | +2.78 / +2.69 / +2.19 | **+8.79 / +9.52 / +9.10** |
| 적분 최대 | 6.36 | **20.00 (포화)** |

이유: gs 를 낮추면 접근이 느려지고 → 밸브가 100 %로 더 오래 열려 레일이 더 깊이
무너지고 → 플랜트가 거의 안 움직이니 **`i_lead` 게이트가 열려** 적분이 포화한다.
"느리게 만들면 안전하다" 가 항상 참이 아니다.

### 3-7. yaml 관련

- **`valve_deadzone.py --write` 는 `valve_deadzone:` 과 `channel_config:` 를 통째로
  다시 쓴다.** 백업(`.bak.<ts>`)이 생기지만, 쓴 뒤 게인이 살아남았는지 반드시 대조한다.
- **`--from` 이 아니라 `--compare <dir> --write` 다** (문서의 `--from` 은 틀렸다).
- **정수/실수 함정**: rclcpp 는 double 파라미터에 int 가 오면 **노드를 죽인다.**
  `--write` 가 `margin_micro_pct: 2.0` 을 `2` 로 적어 `pp_controller` 가 기동에
  실패했다. 증상은 `ros2 node list` 가 비고, `rail_ref` 가 "구독자 없음",
  `pressure_id_seq` 가 접속 재시도만 하는 것이다. 쓰기 직후 검사:

```zsh
python3 -c "
import yaml
d=yaml.safe_load(open('src/can_powerpack/config/powerpack_config.yaml',encoding='utf-8'))
bad=[]
def w(o,p):
    if isinstance(o,dict):
        for k,v in o.items(): w(v,f'{p}.{k}')
    elif isinstance(o,int) and not isinstance(o,bool) and '_pct' in p: bad.append((p,o))
w(d,'')
print('int/double 충돌:', bad or '없음')
"
```

### 3-8. 레일

- **`--pos-rail 200` 은 주장일 뿐 레일을 올리지 않는다.** 별도 터미널에서
  `rail_ref.py --hold-ref 200 30` 을 띄워야 한다. `pressure_id_seq.py` 가 기동 시
  실측과 대조해 경고하고, 실측값으로 도달 범위를 다시 잡는다.
- 레일 루프는 200 을 지령해도 **185 부근에서 머무는 일이 잦다.** 정착을 기다린다.
- 데드존 측정은 **실제 운전에서 쓸 레일**로 맞춰 놓고 한다.

### 3-9. 데드존 측정은 `pp_controller` 를 내리고 한다

`board/pwm_cmd` 발행자가 둘이면 명령이 번갈아 나간다. 런치를 내리고
`can_bridge` 만 띄운다. 그리고 **액추에이터를 뗀다** — 스크립트에 각도 안전장치가
전혀 없고(`--drive-pct 70` bang-bang), 팔이 움직이면 0.40 kPa/s 판정이 오검출된다.

### 3-10. ★ `gain_scale` 은 **실제로 열리는 밸브**의 차압으로 계산해야 한다

20260916 에 찾은 버그다. 대기압 반대편 재라우팅은 밸브를 atm 으로 보내면서
이득 보정은 `e ≥ 0` 이라는 이유로 **micro 의 차압**을 쓰고 있었다.

> 양압 챔버가 팔에 끌려 93 kPa 로 내려간 상황.
> `dp_micro` = 레일 200 − 93 = **107** → `gs = 60/107 = 0.56` → 하한 0.6.
> 그런데 실제로 여는 밸브는 atm 이고 그 구동 차압은 101.3 − 93 = **8**
> → 맞는 값은 `60/8 = 7.5` → 상한 **2.0**.

**3.3 배를 제어기가 스스로 깎고 있었다.** 증상은 "대기압으로 돌아오는 게 너무
느리다" 였는데, 로그에서 atm 은 100 % 구간에 열려 있으니 라우팅만 보고는
안 보인다 — `gs_last_` 를 같이 봐야 보인다.

일반화하면: **밸브를 고르는 조건과 차압을 고르는 조건이 같은 식이어야 한다.**
지금은 `atm_assist` 하나가 이득 보정·적분·라우팅 셋을 모두 지배한다.
비슷한 판정을 또 만들게 되면 그 자리에서 이 절을 떠올릴 것.

### 3-11. atm 으로 대기압을 향할 때는 오버슛 제약이 **없다**

게인을 못 올리는 이유는 늘 "지나칠까 봐" 다. 그런데 atm 밸브가 챔버를
대기압으로 데려가는 동안에는 **물리적으로 지나칠 수 없다** — 대기압에서
유량이 스스로 0 이 된다. 그래서 이 구간만은 활짝 열어도 된다
(`atm_boost_pct` 가 그것이다).

**단, 목표가 대기압이거나 그 너머일 때만 그렇다.** 목표가 챔버와 대기압
**사이**에 있으면(양압 챔버 93 → 목표 97) atm 은 101.3 까지 밀어 버리므로
그때는 지나친다. 코드의 `atm_safe` 가 이 구분이다:

```
sgn·(P_ref − P_atm) ≥ −atm_margin      (sgn: 양압 +1, 음압 −1)
```

이 조건 없이 부스트를 걸면 음압이 망가진다 — 3-1 이 아니라 **바로 이것**이
20260915_175418 에서 음압 내림 오버슛을 +0.40 → +1.12 로 만든 것과 같은 종류의
실수다.

## 4. 진단 방법 — 무엇을 어떻게 재나

튜닝 판단은 전부 아래 네 가지 측정으로 했다. 로그는 `~/result/<ts>/<ts>.csv` 다.

### 4-1. 네 방향 요약

계단마다 오버슛 · ±1/±0.5 도달 시간 · 정착 오차 · |적분| 최대 · 밸브 개도를 낸다.
**반드시 네 방향을 따로** 본다 (양압 올림/내림 · 음압 올림/내림).
`양압 = P− 가 대기압인 구간`, `음압 = P+ 가 대기압인 구간` 으로 갈라낸다.

### 4-2. 한계주기 판정

유지 구간의 뒤 60 % 에서 **압력 p-p · 밸브 토글/s · 각도 p-p** 를 같이 본다.
토글이 있으면 제어, 토글 0 인데 압력이 흔들리면 팔이다.

### 4-3. 무릎 찾기 (개도별 유량)

`pwm − dz` 를 구간으로 잘라 `dP/dt` 를 본다. **차압을 통제**해야 한다
(예: `dp_micro` 60~80 kPa 만). 반대쪽 밸브가 닫힌 표본만 쓴다.

### 4-4. 팔 기여 분리

`enc_bd17_deg` 로 각속도를 내서 회귀한다:
`dP/dt = a·(개도×차압) + b·(dθ/dt)`. 실측 `b = +0.272 kPa/s per °/s`
(팔이 −80 °/s 로 내려오면 압축이 +21.8 kPa/s 로 배기를 상쇄한다).

> 위 분석 스크립트들은 이 세션의 scratchpad 에 있었고 저장소에 안 남겼다.
> 다시 필요하면 같은 방식으로 다시 짜면 된다 — 핵심은 **무엇을 통제하고
> 무엇을 비교하느냐**이지 코드가 아니다.

## 5. 표준 확인 런

압력 제어를 건드린 뒤에는 **반드시 네 방향을 한 번에** 본다. 한 방향만 보다가
다른 방향을 깨뜨린 적이 두 번 있다.

```zsh
python3 src/can_powerpack/scripts/pressure_id_seq.py \
    --axes 1 --scenario 3,4,6 --rep3 1 --rep4 1 --rep6 3 \
    --big-modes pos-only,neg-only --pos-rail 200 --neg-rail 30
```

약 3.5분. 양압 사다리(대기압 복귀 포함) + 음압 사다리 + 양·음압 큰 계단이다.
`--big-modes` 는 이 작업 중에 추가했다.

**같이 봐야 하는 조합**: 큰 계단만 보면 대기압 복귀가 깨진 것을 놓친다
(`i_dp_min_kpa` 를 atm 에도 걸었다가 대기압에서 못 내려온 적이 있다).
